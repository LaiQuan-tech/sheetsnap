# SheetSnap

把複雜 Excel，一鍵變成最適合手機閱讀的流暢網頁。

<https://sheetsnap.link/>

貼上 Google 試算表網址，或選一個 `.xlsx`。**資料不會上傳**——
整個過程都在瀏覽器裡完成，這是純靜態網頁，沒有後端。

## 它做什麼

1. **找出表格在哪。** 真實試算表不是資料表，是排版成表格樣子的文件：
   跨欄大標、空白間隔列、並排的區塊、說明頁、圖表暫存區。
2. **判斷這張表是什麼形狀。** 排程／價目表／通訊錄／狀態清單／
   矩陣報表／帳務明細／一般表格，據此決定手機上怎麼排。
3. **摘要只引述表上原本就有的數字。** 不自己加總——
   加總的結果會跟表上對不起來，而且合計有階層，混著加會得到荒謬的數字。
4. **搜尋與篩選當逃生門。** 摘要不必完整，因為查得到。

## 開發

```bash
npm install
node test.mjs                          # 回歸測試（9 個已知案例）
./corpus-ms/fetch.sh                   # 下載 163 個微軟公開範本
node audit.mjs corpus-ms/files         # 批次體檢
node header-quality.mjs corpus-ms/files # 欄名品質單一指標
node fidelity.mjs corpus-ms/files      # 內容忠實度
```

**改任何規則前後都跑一次。** 放寬一條規則很容易把別的表吸進來——
這四支工具就是為了讓那件事被抓到而存在。

## 呈現不可信時會明講

欄名重複＝兩組並排的欄位被併成一張表，那時每一列都會把不相干的數字配在一起——
**畫面看起來完全正常，但數字是錯的**。這種失敗最危險，所以頁面會在摘要之前
顯示警告，而不是靜靜地把錯誤的數字端出來。

以 163 個微軟範本實測，340 個表格中有 37 個會顯示警告（10.9%）。

## 讀完之後先問「你想怎麼看」

解析完成後不直接渲染，而是給一份**由這份表實際內容生成**的選單：

```
你想怎麼看這份表？
149 筆資料 · 選一個就好，之後可以再換

  照時間看      按「日期」分成 23 段，開啟時跳到今天
  只看某個人員   49 個選項，平均每項 4.6 筆
  直接搜尋      149 筆全部列出，用關鍵字找
```

**選了目的，就大幅縮小「必須判斷正確」的範圍。** 選「照時間看」時，
金額欄判錯完全不影響畫面；原本是所有判斷都得同時對。

**做不到的事不會出現在選單上。** 沒有時間軸就沒有「照時間看」，
沒有可篩選的欄就沒有「只看某人」——選單本身就是誠實的，
跟摘要「引述才顯示」是同一個原則。

選擇會記住（`localStorage`），同一份表第二次打開直接套用，
右上角的「換個看法」可以回去改。

## 每份表一個網址（pudu 的做法）

選好看法之後會給一個分享網址，對方打開就是那個畫面——
沒有輸入框、沒有選單，直接是成品，頁尾註明「用 SheetSnap 製作」。

**Google 試算表**：網址只帶試算表 ID 與看法（`?s=…&v=time`），
收到的人自己的瀏覽器直接讀試算表。零後端，資料不經過我們。
試算表要維持「知道連結的任何人」可檢視。

**上傳的檔案**：檔案在使用者手機裡，唯一不上傳的做法是把資料壓進網址本身
（`?d=…`，lz-string）。只帶目前看的那張工作表，實測預算表 2,121 字、
請假表 670 字。超過 4,000 字就明講放不進去，建議改放 Google 試算表。
