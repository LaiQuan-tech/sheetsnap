# 真實檔案語料

`corpus-ms/` 是 163 份微軟公開範本。它們教了很多，但有個先天限制：**都是空白的**。
填充率、重複值、`$-` 的分佈、併存格的位置，跟真的填過資料的檔案不一樣。
v80 那整條「會計格式的零」的線索，就是因為某份範本「只填了前半年」才浮出來的——
真實檔案會浮出另一批。

這個資料夾是給真實檔案用的，規則只有一條：**檔案不進 repo，只有衍生的 JSON 進 repo**。

## 怎麼跑

```sh
# 檔案放在 corpus-real/files/（已在 .gitignore 裡，推不上去）
node audit.mjs   corpus-real/files --out corpus-real/baseline.json       --private
node gallery.mjs corpus-real/files --out corpus-real/gallery-summary.json --private > corpus-real/gallery.html
```

`--private` 寫出去的 JSON 裡**一個原文都沒有**：

- 檔名換成穩定雜湊（`f3a21b9c`），同一個檔每次跑都是同一個代號，diff 對得起來
- 工作表名換成「檔案代號 › #序號」——原名可能帶人名、客戶、專案，
  但同一個活頁簿裡的表要看得出是同一個檔（它們通常共用結構）
- 前言（`title`）整段丟掉
- **欄名整個丟掉**，只留 `型別:填充率:相異值數`
- 角色只留「有沒有」，不留「叫什麼」
- `reason`／`notes`／`flags` 裡的名字清空：「」裡面、（）裡面、`：`後面三種位置
- gallery 的看法標籤只留 `group`／`rank`／`filter` 這些 id

跑完會把「清理後還會離開這台機器的散文」全部列出來，掃一眼就知道有沒有漏。
終端機輸出跟 `gallery.html` 照原樣產——那是在你自己的機器上看畫面的，不該遮。

### 為什麼連欄名都不留

第一版留著欄名，理由是「引擎的規則大半看欄名（`NAME_HINTS`、合計欄、
人員欄、期間欄），洗掉就等於看不見」。**那個理由錯在一個前提上**：
`colTypes` 記的是「引擎判定的標題列」，而標題列會判錯——
`header-quality` 量出來，會渲染的表裡有 2.9% 判錯。

一份 Google 表單匯出的真正標題列在第 0 列、引擎判在第 4 列。那一行會變成

```
"劉若芊:text:100%:5"  "0915373201:number:…"  "x@gmail.com:email:…"
```

同一個前提也害了 `scrub.mjs`：它的規則是「第 0 列到引擎判定的標題列原樣留著」，
判錯時上面每一列真實資料就全留下來——四位填表人的姓名、手機、Email、公司職稱
因此進了公開 repo。

所以規則只能是：**任何離開這台機器的東西，都不原樣複製任何一格。**

### 代價，以及接下來怎麼補

沒有欄名，就看不見 `NAME_HINTS`、`RE_SUMCOL`、`RE_PERIOD`、`personish`
這些規則有沒有踩對。補法不是「留原文」，是**合成一個會觸發同一組判定的字**：
原欄名中了 `NAME_HINTS.money` 就換成「金額」、中了 `RE_SUMCOL` 就換成「合計」、
中了月份就換成「一月」。這件事驗得出來——漏掉一個判定，那一欄的型別或角色
就會變，結構比對會擋下來。還沒做。

## B：洗成可以進 repo 的案例

A 的代價是我看不到格子內容，所以每一次推理都要多一輪往返。
`scrub.mjs` 把真實檔案洗成「引擎眼裡一模一樣、但內容全換掉」的檔案，
洗完的檔案進 repo，之後任何一台機器都能重跑——不用再把原檔搬來搬去。

```sh
node scrub.mjs corpus-real/files --out corpus-real/scrubbed
# 跑完會印出「原樣留著的字串」，掃過一遍再推
git add corpus-real/scrubbed && git commit -m "真實結構案例" && git push
```

`corpus-real/scrubbed/*.xlsx` 在 `.gitignore` 裡開了例外（`*.xlsx` 本來是全域 ignore）。

### 保住什麼

| | 為什麼 |
|---|---|
| 哪些格子有值、哪些空 | 填充率、標題列評分、切表全看這個 |
| 標題列與前言列的**原文** | `NAME_HINTS`、合計欄、人員欄、期間欄都是看欄名的，洗掉等於沒測 |
| 每一欄的型別、相異值數、重複結構、平均長度、換行 | 判型與角色分配的全部輸入 |
| 日期與時間的原文 | 民國年、點分隔、日月順序——那正是要測的東西 |
| `$-`、`-`、`N/A` | 會計格式的零是結構不是內容（v80 整條線索就是它） |
| 金額的符號、千分位、小數、括號 | `$(635.00)` 的負號、`NT$` 的辨識都靠它 |
| 數字裡 0 的位置 | `NT$5000` 洗完還是 `x000`，整數的「整」留得住；電話的開頭 0 也留得住 |
| 一兩位的純數字 | 數量、工時、件數原樣留著。既不敏感，九個一位數硬換還會撞成一團 |

### 換掉什麼

所有資料格的文字。同一個原值對到同一個假值（**一張工作表共用一本對應表**，
不是一欄一本——一欄一本會把跨欄重複的值拆開，而 `scoreHeader` 有一項
正是「這一列有幾種不同的值」，推一下就足以讓標題列跑掉），
長度一樣、中文對中文、英數對英數、換行位置保留。
信箱換成 `example.com`、網址換成 `example.com`、電話只換數字。
工作表名換成 `S1`、`S2`。

### 洗完會自己驗

對原檔與洗完的檔各跑一次引擎，比對形狀、列數、標題列位置、
每一欄的「欄名:型別:填充率:相異值數」、角色、結構轉換、以及
`sheetVerdict` 的結論。有任何一項不同就印出來並以非零結束——
洗壞了的案例比沒有案例更糟。

### 洩漏檢查是每一次跑都做的

寫檔之前逐格比對：除了刻意保留的三類（空白與「沒有值」、日期時間欄、
一兩位的純數字）之外，任何一格跟原值相同就算洩漏，整個檔不寫。

> 第一版只在 `--selftest` 做這件事，正式跑 `--out` 時只驗結構一致。
> 於是 20 個真實檔案推上公開 repo，**407 格人名電話原樣留著**。
> 原因有兩層：`filler` 把 `值N` 截斷到原值長度，三個字的原值只生得出
> 99 種假值（`值10`…`值99` 之後全部撞在 `值10`）；而 `take()` 的最後一手
> 寫著「生不出來就留原值」。現在 `filler` 用字庫當底數編碼、是單射的，
> 而最後一手改成拋錯——洗不出來就拒絕寫檔，不會悄悄留著。
>
> 教訓是第二層的：測試要跑在會出事的那條路上，不是只跑在想得到的那條。

### 真實檔案又教了四件事

仿真檔過了、163 份微軟範本過了，真實檔案還是洗出四個洞。全部是同一個形狀：
**這一格的內容跟它那一欄的型別不一致**。`detectColumn` 的 `rNum` 門檻是 0.8，
所以一個 number 欄裡混著兩成文字是正常的；scrubber 卻假設了同質性。

| 情況 | 原本的結果 |
|---|---|
| 生成器剛好生出跟原值一樣的值 | 重試只在「撞過」時觸發，等於原值時不重試，一路撞到拋錯 |
| 數值欄裡夾著文字（`分鐘`、`待定`、`アカウント管理`） | `digitSwap` 換不動沒有數字的字串 |
| 數值欄裡夾著半文字（`建坪10土地66`、`NT$400000以上`） | 只換數字，`建坪`、`土地`、`以上` 原封不動 |
| 電話欄裡夾著文字（`已留電話`） | 同上 |

修法：只有「整格只有數字骨架」才走換數字那條，其餘一律當文字洗；
電話是例外（`ext.`、`#`、分隔要留著 `isPhoneish` 才判得出來，而形狀不帶身分）。
重試條件加上「等於原值」。

### 這支程式自己的測試

```sh
node scrub.mjs --selftest
```

拿五個內建的仿真檔跑一遍（台灣報價單、日期橫排的工時表、客戶名冊、
月份橫排預算、歐美 day-first 的 tracker），驗兩件事：

1. **洗完在引擎眼裡一樣** —— 跟上面那段同一套比對
2. **原始內容真的沒留在資料格裡** —— 逐格比對，除了刻意保留的三類
   （空白與「沒有值」、日期時間欄、一兩位的純數字）之外，
   任何一格跟原值相同就算洩漏

第二項是必要的：一支「什麼都不做」的 scrub 也會通過第一項。
實測把 `take()` 改成直接回傳原值，自我測試報 148/148 洩漏並以 1 結束。

驗不過**不一定是洗壞了**。開發時那五個試作檔就有一個驗不過，查出來是
那張表的標題列本來只贏資料列 0.14 分，洗完一推就翻了——
那是引擎的脆弱點，不是洗的問題。這種就直接回報給我。

## 這批檔案最值得包含什麼

`corpus-ms/` 完全沒有涵蓋的：

- **民國年**（`112.3.15`、`民國112年3月15日`）
- **台灣的金額寫法**（`NT$`、`元`、全形 `＄`）
- **日月順序**（台灣用年月日，歐美的 `3/15/24` 跟 `15/3/24` 都有）
- **中文欄名**（`品項`／`負責人`／`到期日` 走的是 `NAME_HINTS` 的另一半）
- **真的填滿的表**（範本的「只填前三個月」是範本特有的，不是真實分佈）

二十到四十份就夠了，種類散一點比數量多有用。
